# T-010 - Règle 100130 : SSRF sur /admin/fetch

- **Date :** 20-10-2026
- **Auteur :** Meghan CRESCI-HUMANN
- **Version Wazuh :** 4.14.9 (single-node)
- **Contrat :** CONTRACT.md v0.3.0-draft (§4.1, §8)
- **Règle testée :** 100130
- **Fichier de règles :** `detection/rules/100130_ssrf.xml`
- **MITRE ATT&CK :** T1190 - Exploit Public-Facing Application
- **Statut :** ✅ Validé (3 cas sur 3)

## Contexte

`POST /admin/fetch` lit le champ `url` du corps et appelle directement `fetch(url)` sans aucune validation (vu dans `routes/admin.js`). Un administrateur - ou un attaquant ayant obtenu une session admin - peut donc forcer le serveur à requêter des ressources internes : services locaux, autres conteneurs, ou l'IP de métadonnées cloud.

L'URL demandée est visible dans `http.request.body` (contrat §4.1, validé en T-006).

## Règle testée

```xml
<rule id="100130" level="10">
  <if_sid>100100</if_sid>
  <field name="http.request.path">^/admin/fetch$</field>
  <field name="http.request.body" type="pcre2">(?i)url=[^&]*(127\.0\.0\.1|localhost|0\.0\.0\.0|169\.254\.169\.254|\[::1\]|file://|gopher://|dict://|169\.254\.|10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\.|metadata)</field>
  <description>SupportDesk: possible SSRF on /admin/fetch to internal target from $(source.ip)</description>
  <mitre><id>T1190</id></mitre>
  <group>web_attack,ssrf,</group>
</rule>
```

### Choix de conception

- **Cibles internes** : la règle alerte quand `url` vise la machine locale (`127.0.0.1`, `localhost`, `[::1]`, `0.0.0.0`), une plage privée (`10.`, `192.168.`, `172.16-31.`), l'IP de métadonnées cloud (`169.254.169.254`, pivot classique d'une SSRF) ou un protocole détourné (`file://`, `gopher://`, `dict://`).
- **Pas d'alerte sur un fetch externe légitime** : une URL publique ne correspond à aucun motif.
- **Restriction à `/admin/fetch`** pour éviter tout faux positif sur d'autres endpoints.

## Limites connues

- **Contournements d'adresse** : une IP interne écrite sous forme décimale (`http://2130706433/` pour 127.0.0.1), octale, ou via un nom de domaine qui résout en interne, n'est pas couverte. Piste d'évasion bonus.
- **Redirections** : une URL externe qui redirige (302) vers une cible interne n'est pas visible dans la requête initiale.
- **Dépend de la journalisation du corps** : si le logger ne renseigne pas `http.request.body`, aucune détection.
- Testé sur échantillons conformes au contrat : à rejouer sur l'application V1.
