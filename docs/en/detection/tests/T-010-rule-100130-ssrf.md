# T-010 - Rule 100130: SSRF on /admin/fetch

- **Date:** 20-10-2026
- **Author:** Meghan CRESCI-HUMANN
- **Wazuh version:** 4.14.9 (single-node)
- **Contract:** CONTRACT.md v0.3.0-draft (§4.1, §8)
- **Rule tested:** 100130
- **Rule file:** `detection/rules/100130_ssrf.xml`
- **MITRE ATT&CK:** T1190 - Exploit Public-Facing Application
- **Status:** ✅ Validated (3 out of 3 cases)

## Context

`POST /admin/fetch` reads the `url` field from the body and directly calls `fetch(url)` without any validation (seen in `routes/admin.js`). An administrator - or an attacker who obtained an admin session - can therefore force the server to request internal resources: local services, other containers, or the cloud metadata IP.

The requested URL is visible in `http.request.body` (contract §4.1, validated in T-006).

## Rule tested

```xml
<rule id="100130" level="10">
  <if_sid>100100</if_sid>
  <field name="http.request.path">^/admin/fetch$</field>
  <field name="http.request.body" type="pcre2">(?i)url=[^&]*(127\.0\.0\.1|localhost|0\.0\.0\.0|169\.254\.169\.254|\[::1\]|file://|gopher://|dict://|169\.254\.|10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\.|metadata)</field>
  <description>SupportDesk: possible SSRF on /admin/fetch to internal target from $(source.ip)</description>
  <mitre><id>T1190</id></mitre>
  <group>web_attack,ssrf,</group>
</rule>
```

### Design choices

- **Internal targets**: the rule alerts when `url` targets the local machine (`127.0.0.1`, `localhost`, `[::1]`, `0.0.0.0`), a private range (`10.`, `192.168.`, `172.16-31.`), the cloud metadata IP (`169.254.169.254`, a classic SSRF pivot) or a hijacked protocol (`file://`, `gopher://`, `dict://`).
- **No alert on a legitimate external fetch**: a public URL matches none of the patterns.
- **Restriction to `/admin/fetch`** to avoid any false positive on other endpoints.

## Cases tested (`wazuh-logtest`)

| Case                     | Sample                 | `url`                                      | Expected          | Obtained       |
| ------------------------ | ---------------------- | ------------------------------------------ | ----------------- | -------------- |
| Cloud metadata           | `ssrf_metadata.jsonl`  | `http://169.254.169.254/latest/meta-data/` | 100130, level 10  | ✅             |
| Local service            | `ssrf_localhost.jsonl` | `http://localhost:9200/_cat/indices`       | 100130, level 10  | ✅             |
| Legitimate external fetch | `fetch_normal.jsonl`  | `https://status.example.com/health`        | no alert          | ✅ 100100 only |

Automatic MITRE enrichment: _Initial Access_, _Exploit Public-Facing Application_.

## Known limitations

- **Address bypasses**: an internal IP written in decimal form (`http://2130706433/` for 127.0.0.1), octal, or through a domain name that resolves internally, is not covered. Bonus evasion lead.
- **Redirects**: an external URL that redirects (302) to an internal target is not visible in the initial request.
- **Depends on body logging**: if the logger does not populate `http.request.body`, no detection.
- Tested on contract-compliant samples: to be replayed on application V1.
